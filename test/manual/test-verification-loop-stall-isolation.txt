Manual smoke test: stall detection ignores read-only fix passes

Scenario: The verification loop's stall detector counts consecutive fix
passes where the failure count does not decrease. Read-only fix passes
(where `fix.wrote` is false) must not increment the stall counter, because
nothing changed on disk — only writes that fail to converge indicate a
genuine stall. A sequence of read-only passes interleaved with write passes
must not trigger premature stall termination.

Config under test:
  ai: [{ provider: 'anthropic', default: true }]
  stages: {
    implement: {
      provider: 'anthropic',
      backend: 'cli',
      verificationConditions: ['yarn typecheck', 'yarn lint']
    }
  }

Preconditions:
  - A target repo with two deliberate failures: one type error and one lint
    violation, in separate files
  - A plan artifact directing the agent to fix both issues
  - ANTHROPIC_API_KEY set in environment
  - DEFAULT_STALL_THRESHOLD is 2 (the default from verification-report.ts)

Verify:
  1. wf issue:implement runs against the target repo
  2. Initial verification detects 2 code failures
  3. First fix pass is read-only (agent diagnoses) — "No files written
     during fix pass — skipping re-verification" appears in console
  4. The stall counter does NOT increment (no "not decreasing" warning yet)
  5. Second fix pass writes a file — re-verification runs, still shows
     2 failures (the agent fixed the wrong thing or introduced a new issue)
  6. The stall counter increments to 1 (first genuine stall)
  7. Third fix pass is read-only again — stall counter stays at 1
  8. Fourth fix pass writes a file — re-verification still shows 2 failures
  9. The stall counter increments to 2, hitting the threshold — console
     shows "Verification failures not decreasing after 2 passes — stopping"
  10. Total fix attempts: 4 (2 read-only + 2 write). Without stall
      isolation, a read-only pass would have been miscounted, causing
      premature termination after only 3 attempts

Wire up: create a minimal target repo with two deliberate failures, a
wf.config.ts with the config above, and a plan artifact listing both files.
Run `wf issue:implement -t TEST-1`. Since the agent's behavior is
non-deterministic, this test is observational — verify the console output
sequence matches the invariants above (read-only passes never trigger stall
warnings, only write passes do).
Teardown: delete the temporary target repo.
