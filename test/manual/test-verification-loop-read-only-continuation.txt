Manual smoke test: verification loop continues after read-only fix passes

Scenario: The implement stage runs with enforced verification scripts that
fail. The CLI agent diagnoses the issue in one fix pass (reads files only,
writes nothing), then applies the fix in a second pass. Prior to the
restructure, the loop exited immediately on `!fix.wrote`, preventing the
agent from ever reaching the second pass. The loop must now continue.

Config under test:
  ai: [{ provider: 'anthropic', default: true }]
  stages: {
    implement: {
      provider: 'anthropic',
      backend: 'cli',
      verificationConditions: ['yarn typecheck']
    }
  }

Preconditions:
  - A target repo with a deliberate type error in a single file (e.g.
    `const x: number = "oops";` in `src/broken.ts`)
  - A plan artifact that tells the agent to fix the type error
  - ANTHROPIC_API_KEY set in environment

Verify:
  1. wf issue:implement runs against the target repo
  2. The initial verification pass detects the type error (console shows
     "Running verification (pass 1)..." followed by failure output)
  3. If the first fix pass only reads files (console shows "No files written
     during fix pass — skipping re-verification"), the loop does NOT exit —
     console shows the agent entering another fix attempt
  4. A subsequent fix pass writes a file (no "No files written" message),
     triggering re-verification ("Running verification (pass 2)...")
  5. Verification eventually passes or the session ends — the loop never
     exits solely because a single fix pass was read-only

Wire up: create a minimal target repo with the type error, a wf.config.ts
with the config above, and a plan artifact JSON pointing at `src/broken.ts`.
Run `wf issue:implement -t TEST-1` and observe console output for the
verification loop sequence.
Teardown: delete the temporary target repo.
